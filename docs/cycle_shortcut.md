# Сокращение пути через циклы (cycle-shortcut)

Описание алгоритма, сокращающего путь, найденный `human_algorithm_to()`.

## Идея

Путь из `human_algorithm_to()` строится по человеческой методике: значения
доставляются на места по одному, и метод не пытается быть оптимальным.
Поэтому в пути почти всегда есть обходы, которые можно срезать.

Срез ищется циклом. Цикл — это слово операций (например `"1231"`),
повторяемое по кругу от некоторого состояния до возврата в него же. Так
устроен `analyze_top_combinations()` в `find_path_iterative`. Все состояния,
пройденные по дороге, образуют замкнутую петлю, выходящую из точки пути и
возвращающуюся в неё.

Ключевое наблюдение: петля, вышедшая из точки `i`, может по дороге задеть
состояние, которое встречается в пути **позже**, в позиции `j > i`. Тогда
участок пути `i → j` длиной `j - i` заменяется участком цикла длиной `m`, и
если `m < j - i`, путь стал короче.

Этим срез через цикл отличается от `short_path_bfs()`: тот обходит окрестность
BFS на глубину 3–9 шагов и находит только близкие срезы. Цикл уходит от точки
далеко — на сотни шагов — и потому достаёт срезы, до которых BFS не дотягивается.

## Вход и выход

**Вход:** путь `P` = последовательность операций длиной `N` (например 1000),
переводящая `start_state` в `final_state`.

**Выход:** путь `P'` с теми же концами и длиной `≤ N`.

Концевые состояния сохраняются: срезы затрагивают только внутренность пути.

## Шаг 1. Выбор точек сегментации

Число точек — параметр `n_points`, а не константа. Вдоль пути выбирается
`n_points` индексов, равномерно со случайным смещением:

```
i_k ≈ k · (N / n_points) + случайное смещение,   k = 1 .. n_points
```

Равномерность даёт покрытие всего пути, смещение — чтобы при повторных
запусках точки не попадали в одни и те же места. Смещение ограничено шагом
сетки, иначе точки сбиваются в кучу.

Индексы сортируются по возрастанию и дедуплицируются.

Сколько брать. Точки — это независимые попытки найти срез, и каждая стоит
одного набора циклов (шаг 3), поэтому стоимость растёт линейно по
`n_points`, а покрытие пути — нет. При большом `N` плотность важнее числа:
`n_points` точек делят путь на отрезки по `N / n_points` операций, и срез
внутри отрезка ищется только от его левого края. Разумный ориентир —
`n_points` порядка `N / 50`, с потолком по времени. Для N = 1000 это те же
20 точек, для N = 1000000 — двадцать тысяч, что уже требует бюджета по
времени, а не полного прохода (см. «Стоимость»).

## Шаг 2. Индекс состояний пути

Путь прогоняется от `start_state` один раз, и все `N + 1` промежуточных
состояний складываются в хеш-словарь:

```
state_index[key(p_j)] = j
```

Ключ — `state_to_key()`, та же функция, что в `StateStore`.

Если состояние встречается в пути несколько раз, хранится **наибольший**
индекс: срез тем выгоднее, чем дальше по пути точка приземления.

Словарь строится один раз на весь путь, а не заново для каждой точки —
проверка «есть ли пересечение» затем стоит O(1).

## Шаг 3. Построение цикла из точки

Для точки `i_k` берётся состояние `p_{i_k}`. От него:

1. Через `find_best_random_combinations()` подбирается несколько слов-комбо
   длиной `combo_length` (по умолчанию 20), отобранных по критериям
   `sort_by = c("longest", "most_unique")` — то есть предпочитаются комбо с
   длинным циклом и разнообразными состояниями.
2. Каждое комбо раскручивается в цикл: слово применяется по кругу, пока
   состояние не вернётся к `p_{i_k}`.
3. На каждом шаге `m` цикла состояние `c_m` проверяется по `state_index`.

Цикл обрывается досрочно, если превышен лимит длины (`max_cycle_len`) —
некоторые комбо дают циклы в сотни тысяч шагов.

## Шаг 4. Оценка пересечения

Пусть на шаге `m` цикла состояние `c_m` совпало с `p_j`.

Пересечение полезно, только если `j > i_k` — приземление должно быть впереди
по пути, иначе срез ведёт назад.

Выигрыш:

```
gain = (j - i_k) - m
```

Оригинальный участок занимал `j - i_k` операций, участок цикла — `m`.
Срез принимается, если `gain > 0`.

Длина всего пути после применения одного среза:

```
N' = i_k + m + (N - j) = N - gain
```

Для каждой точки `i_k` перебираются все её комбо и все шаги цикла, и
запоминается **лучший** срез — с максимальным `gain`.

## Шаг 5. Повтор для всех точек

Шаги 3–4 выполняются независимо для каждой точки. Точки независимы между
собой — общий у них только индекс из шага 2, который лишь читается, — так
что этот шаг распараллеливается без синхронизации, что и делает его
пригодным для больших `n_points`. Результат — список
кандидатов вида `(i_k, j_k, m_k, ops_k, gain_k)`, где `ops_k` — фактические
операции участка цикла. Точки без улучшения отбрасываются.

## Шаг 6. Совмещение срезов

Срезы задают интервалы `[i_k, j_k]` на исходном пути. Два среза совместимы,
только если их интервалы не пересекаются — иначе они переписывают общий
участок и склейка развалится.

Отбор жадный:

1. Кандидаты сортируются по `gain` убыванию.
2. Берётся лучший; следующие принимаются, только если их интервал не
   пересекается ни с одним уже принятым.
3. Принятые сортируются по `i_k` и применяются слева направо.

Новый путь:

```
P' = P[1 .. i_1] + ops_1 + P[j_1+1 .. i_2] + ops_2 + ... + P[j_last+1 .. N]
```

Жадный отбор по `gain` предпочтён пересчёту на уже сокращённом пути:
пересчёт надёжнее в смысле итогового выигрыша, но требует заново строить
циклы для оставшихся точек, а это самая дорогая часть. При желании его
даёт повторный вызов функции на её же результате.

## Проверка

Результат обязательно верифицируется: `P'` применяется к `start_state`, и
итог сверяется с `final_state`. Если проверка не прошла — возвращается
исходный `P`. Срез меняет путь в середине, и молчаливо испорченный путь хуже,
чем несокращённый.

## Стоимость

Доминирует шаг 3 — раскрутка циклов. Для одной точки это
`n_combos × длина_цикла` применений операции, и от `N` она не зависит.
Индекс пути (шаг 2) — один проход, `N` применений. Совмещение (шаг 6) —
сортировка `n_points` элементов.

Итого примерно `N + n_points × n_combos × max_cycle_len` применений операции.

Параметры, которыми регулируется стоимость: `n_points`, `n_samples` и
`n_top` в подборе комбо, `combo_length` и `max_cycle_len`.

### Длинные пути

Путь на миллион операций меняет узкое место. Что упирается:

**Память под индекс.** Шаг 2 хранит `N + 1` состояний по `n` чисел каждое.
При `N = 1000000` и `n = 1000` это порядка 4 ГБ в R-представлении — то есть
индекс в его наивном виде не помещается. Варианты: хранить не состояния, а
их ключи (`state_to_key()` даёт строку, но короче состояния при большом `n`),
либо держать индекс на стороне C++ в `StateStore`, у которого для этого уже
есть хеш-индекс, либо индексировать не каждое состояние, а каждое `s`-е,
теряя часть срезов.

**Бюджет вместо полного прохода.** При `n_points` порядка `N / 50` шаг 3
выполняется десятки тысяч раз. Разумнее задавать не число точек, а лимит
времени или числа обработанных точек, и идти по ним в случайном порядке,
останавливаясь по исчерпании бюджета. Тогда алгоритм даёт частичный
результат на любом `N`, а не отказывается работать.

**Повторные проходы дешевле одного большого.** После применения срезов путь
стал короче, и следующий проход работает уже по укороченному пути с новым
случайным смещением точек. Несколько проходов с умеренным `n_points` дают
больше, чем один проход с огромным, потому что каждый следующий видит уже
изменённую геометрию.

Верификация (проверка `P'` применением) стоит `N'` операций и на длинных
путях не бесплатна, но отказываться от неё не стоит: испорченный путь на
миллион операций искать вручную нечем.

## Отношение к существующим функциям

- `short_path_bfs()` — срезы в пределах BFS-окрестности, дополняет этот
  алгоритм и может применяться после него.
- `find_path_iterative()` — ищет путь между двумя состояниями с нуля,
  используя ту же механику циклов и пересечений; здесь путь уже есть, и
  циклы работают на его сокращение.
- `validate_and_simplify_path()` — проверка валидности и локальные упрощения.
